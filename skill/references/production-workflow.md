# 内容与生产流程

## 一、10 问需求对齐

完整项目开始时梳理以下变量。用户已经提供的信息自动提取并改为反向确认，不重复索取。

1. 核心主题：最想讲明白的一个概念或观点是什么？
2. 目标读者：面向小白、进阶者还是行业从业者？
3. 读者痛点：他们当前的卡点或认知误区是什么？
4. 关键论点：支撑主题的 2–4 个模块或步骤是什么？
5. 案例素材：有哪些案例、数据、截图或踩坑经历可以佐证？
6. 行动建议：读者看完后可以立即执行什么？
7. 视觉基调：科技严谨、经验分享、避坑警告还是轻松干货？
8. 内容篇幅：最合理的知识单元体量是多少？
9. 首图钩子：用哪条痛点、数字或对照制造停留？
10. 结尾转化：引导评论、收藏、关注还是完成一个动作？

同时确认三项全局配置：`博主署名`、`视觉主色调`、`目标卡片尺寸`。未提供时分别使用空值、`#1E60FF` 和 `1080×1440px`。

用户要求直接执行时，不因可选问题停下。根据材料填写答案，把无法确认的内容列为“生成假设”，不得虚构用户经历、数据或来源。

## 二、内容规划与动态分页

先输出项目摘要：

| 决策项 | 结果 |
| --- | --- |
| 核心主题 | 一句话中心结论 |
| 目标读者 | 人群与知识基础 |
| 主要痛点 | 当前卡点或误区 |
| 关键模块 | 2–4 个知识单元 |
| 视觉配置 | 署名、主色、尺寸、基调 |
| 事实状态 | 已核验、待核验、个人观点 |
| 总页数 | 由知识单元数量决定 |

通常规划 3–7 张。只有内容确实需要时才增加页数，不为凑 9 张水字数或拆碎知识。

页面角色：

- P1 封面：痛点大标题、核心人群标签、简短副标。
- P2 至 PN-1 正文：每页讲透一个模块，采用“结论先行＋清单、对比、流程或结构图”。
- PN 尾页：复盘核心要点、给出一个落地动作，并按用户目标设置互动引导。内容不足时与最后一页正文合并。

页面蓝图使用以下字段：

| 页码 | 页面任务 | 标题 | 正文要点 | 信息结构 | 视觉元素 |
| --- | --- | --- | --- | --- | --- |
| 01/YY | 封面钩子 | 不超过两行 | 一句副标 | 主视觉 | 主题图形 |

## 三、P1/P2 样板确认

1. 先交付整套内容大纲。
2. 提供 P1 封面和 P2 正文的完整文字、布局说明与视觉规格；具备渲染能力时输出两张实际样图。
3. 请用户确认信息密度、行文调性、主色、字号层级和手机端可读性。
4. 把确认结果锁定为本次任务的统一规格，再生成其余页面。

## 四、批量生产

- 文本、清单、对比、流程和架构图优先使用 HTML/CSS 或 SVG 渲染。
- 摄影、人物、插画、复杂场景或材质使用图像生成，再在可编辑布局中叠加中文文字。
- 只在样板确认后批量生成；用户明确允许跳过确认时除外。
- 为每页保留可编辑源文件并导出 PNG，文件名使用 `01-cover.png`、`02-topic.png` 等可排序格式。

## 五、发布文案

- 标题：给出 3 个候选，保留具体信息和搜索关键词，不使用夸张承诺。
- 正文：按“问题—核心结论—案例或证据—读者行动”组织。
- 标签：使用 5–8 个与主题、人群和场景直接相关的标签。
- 评论引导：提出能让读者分享具体经历的问题，避免“你怎么看”类空泛问法。
